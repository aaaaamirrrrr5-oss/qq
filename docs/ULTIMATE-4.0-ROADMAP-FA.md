# Site Manager 4.0 — Ultimate Professional Edition

وضعیت این بسته: **نسخه توسعه‌ای 4.0.0، نه انتشار نهایی**

## هدف محصول
یک اپلیکیشن حرفه‌ای مدیریت چند سایت WordPress و WooCommerce با تجربه کاربری یکپارچه، رابط فارسی/انگلیسی/عربی، امنیت قابل ممیزی و امکانات عملیاتی واقعی.

## آنچه در این بسته واقعاً پیاده‌سازی شده

- مرکز کنترل حرفه‌ای با اطلاعات محیط، وضعیت اتصال، تعداد سایت‌های ثبت‌شده و نتیجه واقعی دو endpoint سلامت و به‌روزرسانی.
- صفحه ابزارهای میانبر برای سلامت وردپرس، نشست‌های امنیتی، به‌روزرسانی‌ها و گزارش فعالیت.
- پشتیبان‌گیری رمزگذاری‌شده با PBKDF2-SHA256 و AES-256-GCM؛ گذرواژه حداقل ۱۲ نویسه؛ salt و IV تصادفی؛ احراز اصالت ciphertext؛ رد گذرواژه اشتباه و فایل دستکاری‌شده.
- پشتیبان شامل نام و URL سایت‌ها، کلید اصلی اتصال و تنظیمات نمایشی است. توکن‌های کوتاه‌عمر و شناسه دستگاه عمداً منتقل نمی‌شوند؛ پس از بازیابی، دستگاه باید نشست تازه دریافت کند.
- بازیابی با اعتبارسنجی ساختار و URL، سقف اندازه فایل، سقف ۱۰۰ سایت، ادغام امن سایت‌های تکراری و حفظ اعتبارنامه‌های فعلی برای URLهای موجود.
- ذخیره مجدد کلیدها در Android Keystore از مسیر Native Plugin؛ در پیش‌نمایش وب، ذخیره‌سازی طبق رفتار قبلی برنامه انجام می‌شود.
- استایل responsive اختصاصی برای مرکز کنترل و ورود آن به هاب اصلی.
- تست‌های جدید رمزنگاری و یکپارچگی UI/کنترل مرکز.

## قابلیت‌های موجود از نسخه‌های قبل که حفظ شده‌اند

- مدیریت محتوا، رسانه، دیدگاه‌ها، کاربران، افزونه‌ها، پوسته‌ها و تنظیمات مجاز وردپرس.
- بخش‌های فروشگاهی موجود برای سفارش‌ها، محصولات، مشتریان، کوپن‌ها، CSV و تغییر گروهی قیمت.
- چند سایت با اعتبارنامه جداگانه، نشست دستگاه، ذخیره امن Android Keystore، صف آفلاین و تنظیمات ظاهری.
- زبان‌های فارسی، انگلیسی و عربی با جهت RTL/LTR و واژه‌نامه پویا؛ ترجمه کامل تمام متن‌های برنامه و متن‌های دریافتی از افزونه‌ها هنوز تضمین نشده است.
- تم روشن/تیره، پیروی از تنظیم دستگاه، کاهش حرکت و برخی بهبودهای دسترس‌پذیری.

## محدودیت مهم ورودی این تحویل

ZIP ورودی 3.13.9 شامل سورس اپ Android/Capacitor، فایل‌های `www`، کد Native و مستندات/تست‌ها بود؛ **سورس PHP افزونه Site Manager Bridge در آن وجود نداشت**. بنابراین در این نسخه هیچ ادعایی درباره رفع آسیب‌پذیری‌های سمت سرور، تغییر مجوز endpointها یا سازگاری زنده WordPress/WooCommerce مطرح نمی‌شود. برای تکمیل این بخش باید ZIP یا پوشه کامل سورس افزونه Bridge نیز در اختیار توسعه باشد.

## تست‌های اجراشده در محیط فعلی

- `npm run check:js`: موفق.
- `npm test`: موفق؛ شامل تست‌های ترجمه، منطق رابط، مجوزهای UI، امنیت نشست، رمزنگاری پشتیبان و کنترل مرکز.
- `tests/backup-crypto.test.cjs`: round-trip رمزنگاری، رد گذرواژه اشتباه، تشخیص دستکاری ciphertext و حداقل طول گذرواژه.
- `tests/control-center.test.cjs`: بارگذاری assetها، مسیر دسترسی، endpointهای زنده، اتصال رمزنگاری و merge امن.
- `tests/editor-dom.test.cjs`: در این محیط به دلیل نبود `jsdom` اجرا نشده است؛ اسکریپت جداگانه `npm run test:dom` دارد.
- `tests/ux-browser.test.cjs`: به دلیل نصب نبودن Playwright فقط skip شده است.
- APK واقعی، نصب روی دستگاه، اتصال به سایت staging و تست restore واقعی هنوز انجام نشده‌اند.

## گام‌های لازم تا انتشار 4.0 نهایی

1. دریافت و ممیزی سورس کامل Bridge PHP؛ اصلاح P0های امنیتی پیش از افزودن API جدید.
2. تست endpointها با نقش‌های read/editor/admin و تست منفی دسترسی در WordPress staging.
3. تکمیل ترجمه با پوشش همه رشته‌ها و بازبینی UI در سه زبان.
4. تکمیل داشبورد تجمیعی و جداسازی tenantها.
5. پیاده‌سازی بکاپ واقعی WordPress و restore آزمایشی.
6. اتصال اختیاری AI با تأیید کاربر، allow-list و محدودیت هزینه.
7. تست DOM و مرورگر، ساخت APK/AAB، نصب و آزمون روی دستگاه واقعی.
